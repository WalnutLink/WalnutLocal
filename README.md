# Walnut Local

本机上的判断仓库。两件东西，一件事：**让 agent 自己查自己。**

```
WalnutLocal/
├── server.py          AgentFullMemory：判断的存取（MCP，stdio，零依赖）
├── ledger.py          本地自审账本：找矛盾、找过期、找没出处的
├── memory/
│   ├── items.jsonl    判断本体（唯一权威位置）
│   └── MEMORY.md      自动生成的人读版
└── ledger.db          我审过什么、发现什么、怎么处置的
```

不对外、不发布、不参与任何公开记录。对外那一层在 walnutlink.ai，是另一件事。

---

## 为什么要分两个文件

`items.jsonl` 存**判断**。`ledger.db` 存**审过的痕迹**。

不合并，是因为「同一件事存两处，必有一处腐化」——2026-11-01 治理记忆时踩过这个坑：
20 条记忆里 8 条是 skill 里已有内容的副本，改一处另一处就烂，还挤爆配额。

所以这里划一条线：**判断只有一个权威位置，处置记录只有一个权威位置，两者靠 id 关联。**

---

## 一、AgentFullMemory：只存判断，不存事实

一般记忆服务器存事实、对话摘要、偏好。没有一家存「错了要付代价的那句话」——
带出处、带到期、带一句明确的「什么算看错」。

四个工具：

| 工具 | 干什么 |
|---|---|
| `memory_propose` | 记一条判断，状态是 `proposed`，永远不是「真的」 |
| `memory_recall` | 搜，出处一起返回；没搜到返回 `no_match`，不许补 |
| `memory_audit` | 重复、无出处、永远结不了账、到期没结、容量 |
| `memory_ledger` | 提升 / 结账 / 列未结 |

三条规则，每条都来自一次失败：

**1. 自己写自己的记忆，会把模型的猜测记成事实。**
所以一切以 `proposed` 入场，提升是另一次明确调用。

**2. 没有出处的记忆没法核对，所以它永远不会错。**
`src` 可以空着，但每次召回都会标 `(none - unverified)`。不是禁止记无出处的想法，
是让无出处这件事永远可见，而不是悄悄变成事实。

**3. 「没记过」和「记过是错的」是两个答案。**
召回不命中返回 `no_match` 加一句 *do not infer; say it was never recorded*。
会拿合理猜测填空的记忆，比没有记忆更糟。

一条记录：

```json
{
  "id": "afm_248a1552d2",
  "kind": "judgment",
  "claim": "沪电股份三季度毛利率升 3.1 个点主要来自 AI 服务器高多层板占比提升",
  "src": "2026 三季报 第 12 页 营业成本附注",
  "scope": "沪电股份 002463",
  "resolve_by": "四季报高多层板占比回落但毛利率仍升",
  "due": "2027-04-30",
  "status": "proposed",
  "outcome": ""
}
```

`outcome` 三态：`hit` / `miss` / `error`。**`error` 不是 `miss`**——「数据没拿到」和
「判断错了」是两件事，混在一起，战绩就成了假的。

## 二、ledger.py：自审，不是发布

只查四类问题——这四类就是记忆腐化的四种形态：

| 类 | 判据 |
|---|---|
| `overdue` | 状态 active 且到期日已过 |
| `no_resolve` | 是 judgment 却没写「什么算看错」——等于免责声明 |
| `no_src` | 没有出处，以后没法核对 |
| `contradiction` | 同一范围里两条方向相反，且文本相似度 ≥ 0.55 |

第四类要动脑子，用启发式：同 scope + 文本相似 + 方向词相反（上升/下降、增加/减少、
改善/恶化…）。**启发式一定会有误报**，所以每条都能被标记处置过，处置过的下次不再报。

```bash
python3 ledger.py audit                              # 该审的
python3 ledger.py review <target> <issue> fixed "说明"   # 处置掉
python3 ledger.py log                                # 处置历史
```

`audit` 有发现时退出码 1——可以直接挂定时任务，有问题就出声。

## 三、装进 agent

### Hermes

```bash
hermes mcp add walnutlocal --command python3 --args /path/to/WalnutLocal/server.py
```

### DSH

追加到 `$DSH_HOME/profiles/<profile>/cordis.patch.yml`（所有 profile 就放
`$DSH_HOME/cordis.patch.yml`）。不要覆盖已有文件：

```yaml
- insert:
    - id: memory-walnutlocal
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: walnutlocal
        transport: stdio
        command: python3
        args:
          - /path/to/WalnutLocal/server.py
        env:
          WL_MEMORY_DIR: /Users/you/WalnutLocal/memory
```

DSH 把它暴露成 `mcp__walnutlocal__memory_recall` 这样。

### 任意 MCP 客户端

`python3 server.py`，stdio，逐行 JSON-RPC 2.0，答 `initialize` / `tools/list` /
`tools/call` / `ping`。零依赖，单文件。

## 四、三步验证

1. **会话 A**：让它记一条带出处的判断，确认调到 `memory_propose` 并拿到 id。
2. **会话 B**（新会话，同一存储）：问一个需要它的题，确认调到 `memory_recall`，
   并且把 `src` 原样念出来。
3. **问一个从没记过的东西**，确认它答「没记过」而不是编。**这一步最重要。**

顺手验自审：

```bash
python3 ledger.py audit
python3 server.py --audit     # 记忆自身的健康报告
```

## 五、故意不做的事

- **不做 embedding、不做语义搜索。** 按 claim/why/scope/tags 做子串匹配。
  八成准的语义召回，比精确召回加一句「没记过」更糟。
- **不自动合并冲突。** 两条矛盾的判断都留着，由人或 agent 处置，服务器不偷偷选边。
- **不上云、不要账号、不同步。** 它就是几个文件。
- **不存事实。** 行情、公告、电话会原文放别处。这里放的是关于它们的判断。
- **不发布。** 这一层没有任何通往公开层的接口。要对外说话，是另一个系统的事。

---

## 六、为什么要把它和公开层分开

本地这一层的目的是**自省**：我到底依据什么这么想，三个月后能不能查出来我错了。

一旦给它接一条通往公开的管道，记判断的动机就会变成「这条能不能发」，
而不是「这条以后能不能被我查出错」。动机一错，账本就变成自我宣传的草稿箱。

所以：**同一套字段，两个用途。对内自省，对外沟通。中间不连管道，只共享格式。**

## 索引表：先收敛，再比较

判断库有几千条之后，每轮对话都把用户这句话跟每一条算一次分，是浪费。
`index.py` 把这件事拆成两级：先用**键**把候选收敛到几十条，再只对这几十条精排。

### 四层结构

```
实体表    entity -> {id}      哈希 O(1)。沪电 / 沪电股份 / 002463 指向同一个键
键表      3-5 字串 -> {id}    只收出现一两次的串，首尾不是虚词
话题表    4-5 字串 -> {id}    出现 3 次以上的高频名字（中际旭创这类）
词组表    bigram -> {id}      带 IDF。出现在 30% 以上条目里的不进表
关系边    实体共现 -> 权重    一跳扩散，提到"存储涨价"能想起写具体公司的那几条
```

键表是从数据里长出来的，不是手工维护的词典。判据：出现次数极少 + 首尾非虚词 +
不是更长同一个串的一部分。**中文里专名和短语在统计上长得一样**，只按"少见"筛会长出
"还能不能""那份财报"；只加虚词边界又会把"中际旭创"这类名字误杀（"中"曾被当成虚词）。

### 五条原则

1. **分母要算上"库里没有的东西"**。只统计库中存在的词，会让"今天天气怎么样"
   因为恰好撞上一个词而得到 100% 覆盖度。没见过的词按最高权重计入分母。
2. **名字是硬条件，不是加分项**。问"沪电那条"，就不能把没提沪电的条目排上来，
   哪怕它靠"判断""看错"这类套话凑出更高的字面分。
3. **不索引套话**。`resolve_by` 里"什么情况算我看错"这半句本身没有信息量，
   建进去会让每条带这套话的记录在所有"算不算看错"的问题上互相干扰。
4. **2 个字的串不算键**。68 条的库里"问题""东西"都只出现一两次，但它们是偶然撞上的，
   不是键。中文键最少 3 个字，2 个字的只留实体表里的名字和六位代码。
5. **没有键命中就基本不触发**。退路是"稀有词同时撞上 3 个且覆盖度过 45%"，
   这条退路越宽，无关问题误触发的越多——实测 45% 是当前数据上的平衡点。

### 多段输入：当前这句是主语，上文是线索

真实对话里最常见的追问是"那这个季度能不能撑住""那钱落在谁身上"——
单看这句谁也不知道在说谁。所以钩子送两段进来：

```
(用户当前这句, 权重 1.0)  (我上一轮说的话的骨架, 权重 0.4)
```

合并方式是**取更像的那一段**，不做加权平均。这一条是试出来的：加权平均把上文的证据
稀释掉，12 条追问只中 7 条；直接拼成一坨反而中 10 条。但拼接在长上文下会崩——
用户这句十几个字，上文几百字，字面覆盖全被上文占了。所以按段算分、取最大、
上文乘 0.85 的折扣。

### 实测一：单轮（35 条手标正例 + 10 条无关问题）

| 方案 | 第一名 | 前三名 | MRR | 无关问题误触发 | 平均注入字数 | p50 |
|---|---|---|---|---|---|---|
| 全量塞进上下文 | 0.057 | 0.057 | 0.057 | — | 9,379 | — |
| 关键词搜索（全部命中） | 0.429 | 0.429 | 0.429 | 5/10 | 61 | — |
| 逐条打分（旧） | 0.857 | 0.914 | 0.886 | 2/10 | 226 | 0.8ms |
| **索引表（新）** | **0.857** | **0.914** | **0.886** | **1/10** | **155** | **0.4ms** |

准确率追平，注入字数少 31%，误触发少一半，快一倍。

### 实测二：多轮（用户这句没头没尾，靠上文接住）

短上文（约 60 字，12 条正例 + 3 条无关）：

| 方案 | 第一名 | 前三名 | 浮错 | 没浮 | 误触发 |
|---|---|---|---|---|---|
| 只用当前这句 | 0.167 | 0.167 | 1 | 9 | 0/3 |
| 拼成一坨 | **0.833** | **0.917** | 1 | 0 | 0/3 |
| 分段加权（新） | 0.750 | 0.917 | 1 | 0 | 0/3 |

长上文（900+ 字，5 条）：

| 方案 | 第一名 | 前三名 | 浮错 | 没浮 |
|---|---|---|---|---|
| 只用当前这句 | 0.000 | 0.000 | 0 | 5 |
| 拼成一坨 | 0.600 | 0.600 | 0 | 2 |
| **分段加权（新）** | **0.800** | **0.800** | 0 | 1 |

17 条合起来：拼接 13/17，分段加权 15/17。真实对话里上文通常很长，所以选分段加权。

### 实测三：库变大以后（每轮一次查询的 p50）

| 库大小 | 前三名 | 逐条打分 | 索引表 | 倍数 |
|---|---|---|---|---|
| 68 | 0.914 | 1.1ms | 0.40ms | 2.7× |
| 500 | 0.914 | 7.9ms | 0.40ms | 19× |
| 2,000 | 0.943 | 31.6ms | 0.40ms | 75× |
| 10,000 | 0.943 | 159ms | 0.40ms | 378× |
| 50,000 | 0.943 | 747ms | 0.40ms | 1,847× |

**延迟跟库的大小脱钩**，命中率没掉。建表一次性 14ms（68 条）/ 4.1 秒（5 万条），
按文件 mtime 缓存，写入新判断后自动重建。

### 已知局限

- **68 条以内看不出速度收益**，索引有固定开销，跟全量扫是一个量级。
- 测试集只有 52 条（35 单轮 + 17 多轮），阈值是在这个规模上定的，随库变大会过拟合。
- 中文没做分词。二元组 + IDF 能长出停用词表，但挡不住所有短语。
- 不用向量检索。同类工作实测 20 种向量配置在个性化记忆上都不显著，本库又是有界、高重复的。
- 三条已知漏：**纯话题相似没有专名**（"那天A股大跌是不是三季报引起的"）、
  **中文名只出现在英文条目里**（"飞艇气囊"）、**名字不在任何被索引字段里**（"北方华创"）。
